# Mutations et effets secondaires

- Utilisez la fonction [mutate](https://swr.vercel.app/docs/mutation#mutate) liée de SWR et la fonction `mutate` retournée par `useSWRConfig()` lorsque l'utilisateur effectue une action qui change l'état du backend. Cela garde le cache SWR partagé d'O3 synchronisé et évite de recharger la page pour voir les changements. Préférez `useSWRConfig().mutate` à l'import de la fonction globale `mutate` depuis `swr` dans les composants, car O3 fournit son propre cache SWR via le décorateur de composant.

  Il y a deux approches principales pour la mutation avec SWR :

  1. Utilisation de la fonction [mutate liée](https://swr.vercel.app/docs/mutation.en-US#bound-mutate) retournée par votre hook de ressource :
  
  ```tsx
  import { restBaseUrl, useOpenmrsSWR } from '@openmrs/esm-framework';

  // Utilisation de mutate liée pour mettre à jour une ressource spécifique
  const patientUrl = `${restBaseUrl}/patient/${patientUuid}`;
  const { mutate } = useOpenmrsSWR<Patient>(patientUrl);

  const handleSave = async (updates: Partial<Patient>) => {
    try {
      await savePatient(updates);
      await mutate();
      showSnackbar({ title: t('patientSaved', 'Patient enregistré avec succès') });
      await closeWorkspace({ discardUnsavedChanges: true });
    } catch (error) {
      showSnackbar({ 
        kind: 'error',
        title: t('errorSavingPatient', 'Erreur lors de l'enregistrement du patient'),
        subtitle: error instanceof Error ? error.message : t('unknownError', 'Erreur inconnue'),
      });
    }
  };
  ```

  `useOpenmrsSWR<T>` met en cache `FetchResponse<T>`. Ne passez donc des données explicites à `mutate` que lorsque vous avez la même forme de réponse. Sinon, revalidez la ressource après une mutation réussie.

  2. Utilisation de `useSWRConfig().mutate` pour des mises à jour de cache plus larges :

  ```tsx
  import { restBaseUrl } from '@openmrs/esm-framework';
  import { useSWRConfig } from 'swr';

  const { mutate } = useSWRConfig();

  // Mettre à jour toutes les ressources de visite en cache qui peuvent afficher cette visite supprimée
  const handleDeleteVisit = async (patientUuid: string, visitUuid: string) => {
    try {
      await deleteVisit(visitUuid);
      
      // Mettre à jour les listes de visites en cache pour ce patient
      await mutate(
        (key) => typeof key === 'string' && key.startsWith(`${restBaseUrl}/visit?patient=${patientUuid}`),
      );
      
      // Mettre à jour les données de la visite spécifique
      await mutate(`${restBaseUrl}/visit/${visitUuid}`);
      
      showSnackbar({ title: t('visitDeleted', 'Visite supprimée avec succès') });
    } catch (error) {
      showSnackbar({ 
        kind: 'error',
        title: t('errorDeletingVisit', 'Erreur lors de la suppression de la visite'),
        subtitle: error instanceof Error ? error.message : t('unknownError', 'Erreur inconnue'),
      });
    }
  };
  ```

  Un filtre de clé ne peut pas rafraîchir les listes chargées avec [`useOpenmrsInfinite`](https://github.com/openmrs/openmrs-esm-core/blob/main/packages/framework/esm-framework/docs/functions/useOpenmrsInfinite.md) ou [`useOpenmrsFetchAll`](https://github.com/openmrs/openmrs-esm-core/blob/main/packages/framework/esm-framework/docs/functions/useOpenmrsFetchAll.md). Ces deux hooks reposent sur `useSWRInfinite`, et SWR ignore les entrées de cache de `useSWRInfinite` lorsqu'il applique un filtre de clé. Le filtre ci-dessus ne rafraîchit donc rien pour ces listes. Parcourir `cache.keys()` et appeler `mutate` sur la clé de l'une de ces listes ne suffit pas non plus, car seule la première page est récupérée à nouveau et les pages suivantes restent périmées. À la place :

  - Dans le composant qui charge la liste, appelez la fonction `mutate` renvoyée par `useOpenmrsInfinite` ou `useOpenmrsFetchAll`. Appelée sans argument, elle récupère à nouveau toutes les pages chargées.
  - Si le rafraîchissement doit se faire ailleurs, par exemple dans une modale ou une autre extension, transmettez-lui cette fonction `mutate` (par exemple, en tant que prop de la modale), ou chargez la liste avec une seule clé `useSWR` et un fetcher qui suit les liens `next`. Un filtre de clé peut correspondre à cette clé, et sa revalidation récupère à nouveau toutes les pages.

  ```tsx
  import { openmrsFetch, restBaseUrl } from '@openmrs/esm-framework';
  import useSWR from 'swr';

  interface PaginatedResponse<T> {
    results: Array<T>;
    links?: Array<{ rel: string; uri: string }>;
  }

  // Suit les liens `next` jusqu'à ce que toutes les pages soient chargées
  async function fetchAllPages<T>(url: string): Promise<Array<T>> {
    const results: Array<T> = [];
    let nextUrl: string | null = url;

    while (nextUrl) {
      const response = await openmrsFetch<PaginatedResponse<T>>(nextUrl);
      results.push(...(response.data?.results ?? []));
      nextUrl = getNextPageUrl(response.data?.links);
    }

    return results;
  }

  function getNextPageUrl(links: PaginatedResponse<unknown>['links']): string | null {
    const uri = links?.find((link) => link.rel === 'next')?.uri;
    if (!uri) {
      return null;
    }

    // Les liens `next` sont absolus, donc utiliser l'origine courante pour que les proxys frontend continuent de fonctionner
    const nextUrl = new URL(uri);
    nextUrl.host = window.location.host;
    nextUrl.protocol = window.location.protocol;
    return nextUrl.toString();
  }

  // Une seule clé de cache pour toute la liste, afin que le filtre de clé ci-dessus rafraîchisse toutes les pages
  export function usePatientVisits(patientUuid: string) {
    const url = `${restBaseUrl}/visit?patient=${patientUuid}&v=custom:(uuid,display,startDatetime)`;
    return useSWR<Array<Visit>>(url, fetchAllPages<Visit>);
  }
  ```

  [`useOpenmrsPagination`](https://github.com/openmrs/openmrs-esm-core/blob/main/packages/framework/esm-framework/docs/functions/useOpenmrsPagination.md) repose sur `useSWR`, donc un filtre de clé peut atteindre ses entrées de cache. Ses clés de cache sont toutefois des URLs absolues dont la chaîne de requête est réencodée. Faites donc correspondre le chemin de la ressource avec `includes` plutôt qu'avec `startsWith` :

  ```tsx
  await mutate((key) => typeof key === 'string' && key.includes(`${restBaseUrl}/visit?patient=${patientUuid}`));
  ```

- Lors de la mutation de données qui apparaissent à plusieurs endroits dans votre application, assurez-vous de mettre à jour toutes les entrées de cache pertinentes. Vous pouvez utiliser la fonction `mutate` avec un matcher de clé pour cibler des entrées de cache spécifiques. Voici un exemple de mise à jour des données d'adhésion à une cohorte :

  ```tsx
  const getCohortMembershipUrl = (patientUuid: string) => 
    `${restBaseUrl}/cohortm/cohortmember?patient=${patientUuid}&v=custom:(uuid,patient:ref,cohort:(uuid,name,startDate,endDate))`;

  // Fonction mémorisée pour mettre à jour le cache d'adhésion à la cohorte
  const useMutateCohortMembers = (patientUuid: string) => {
    const { mutate } = useSWRConfig();

    return useCallback(() => {
      const key = getCohortMembershipUrl(patientUuid);
      return mutate(
        // Ne muter que les entrées de cache qui correspondent exactement à cette clé
        (cacheKey) => typeof cacheKey === 'string' && cacheKey === key
      );
    }, [patientUuid]);
  };
  ```

  Et voici un exemple d'utilisation du hook mutate dans un gestionnaire de soumission :

  ```tsx
  const handleSubmit = useCallback(async () => {
    try {
      await Promise.all(
        selected.map(async (selectedId) => {
          const patientList = data.find((list) => list.id === selectedId);
          if (!patientList) {
            return;
          }

          try {
            await patientList.addPatient();
            // Mettre à jour les données d'adhésion à la cohorte
            await mutateCohortMembers();
            showSnackbar({
              title: t('successfullyAdded', 'Ajouté avec succès'),
              kind: 'success',
              isLowContrast: true,
              subtitle: `${t('successAddPatientToList', 'Patient ajouté à la liste')}: ${patientList.displayName}`,
            });
          } catch {
            showSnackbar({
              title: t('error', 'Erreur'),
              kind: 'error',
              subtitle: `${t('errorAddPatientToList', 'Patient non ajouté à la liste')}: ${patientList.displayName}`,
            });
          }
        }),
      );
    } finally {
      closeModal();
    }
  }, [data, selected, closeModal, t, mutateCohortMembers]);
  ```
