# Implémentation : sous le capot

L'état de Workspace v2 est géré par le store d'espaces de travail du framework. La plupart du code applicatif doit utiliser les APIs publiques au lieu de modifier directement le store :

- `launchWorkspace2` pour ouvrir ou restaurer un espace de travail
- `launchWorkspaceGroup2` pour ouvrir un groupe avant le premier lancement de workspace lorsque votre application a besoin d'un contexte de groupe ou d'un menu d'actions app-wide
- `closeWorkspaceGroup2` pour fermer le groupe actuel
- `Workspace2DefinitionProps.closeWorkspace` pour fermer un espace de travail depuis son composant
- `Workspace2DefinitionProps.launchChildWorkspace` pour ouvrir des espaces de travail enfants dans la même fenêtre

## Forme du store

Le store v2 suit les définitions enregistrées et l'interface actuellement ouverte :

- `registeredGroupsByName` - définitions de groupes enregistrées depuis `workspaceGroups2`
- `registeredWindowsByName` - définitions de fenêtres enregistrées depuis `workspaceWindows2`
- `registeredWorkspacesByName` - définitions d'espaces de travail enregistrées depuis `workspaces2`
- `openedGroup` - le groupe actuellement ouvert et ses props de groupe
- `openedWindows` - les fenêtres ouvertes dans ce groupe, y compris la pile d'espaces de travail de chaque fenêtre
- `isMostRecentlyOpenedWindowHidden` - indique si la fenêtre au premier plan est actuellement masquée
- `workspaceTitleByWorkspaceName` - les titres fournis par chaque wrapper `<Workspace2>` rendu

Chaque fenêtre ouverte contient `windowName`, `props`, `maximized` et `openedWorkspaces`. Chaque espace de travail ouvert stocke son `workspaceName`, ses props de lancement, son `uuid` généré et son état `hasUnsavedChanges`.

## Lire le contexte d'un espace de travail

Dans un composant d'espace de travail, utilisez les props fournies par `Workspace2DefinitionProps` ou le hook `useWorkspace2Context` pour lire le contexte de l'espace de travail courant :

```tsx copy
import { useWorkspace2Context } from '@openmrs/esm-framework';

export function WorkspaceDebugPanel() {
  const { workspaceName, windowName, workspaceProps, windowProps, groupProps } = useWorkspace2Context();

  return (
    <pre>
      {JSON.stringify(
        {
          workspaceName,
          windowName,
          workspaceProps,
          windowProps,
          groupProps,
        },
        null,
        2,
      )}
    </pre>
  );
}
```

Le store d'espaces de travail de bas niveau est un détail d'implémentation. Préférez les APIs publiques de lancement, fermeture, groupe et contexte sauf si vous travaillez dans le framework lui-même. Si un composant doit fermer toute la fenêtre au lieu de se fermer seulement lui-même avec ses espaces de travail enfants, appelez `closeWorkspace({ closeWindow: true })`.

## Afficher un espace de travail en dehors de la fenêtre d'espace de travail

`<ExportedWorkspace>` affiche le contenu d'un espace de travail enregistré (les enfants de son `<Workspace2>`) dans votre propre arbre de composants, indépendamment du système global de fenêtres d'espace de travail. Il émule la fenêtre qui contient l'espace de travail : `launchChildWorkspace` et `closeWorkspace` naviguent donc à l'intérieur du composant, à l'aide d'un store local. Il n'affiche aucun élément d'interface (ni barre de titre, ni agrandissement, masquage, fermeture ou icône) ; l'appelant peut donc afficher les siens.

```tsx copy
import { ExportedWorkspace } from '@openmrs/esm-framework';

<ExportedWorkspace name="gastrodynamics-form-workspace" workspaceProps={{ patientUuid }} />;
```

Modifier `name`, `workspaceProps`, `windowProps` ou `groupProps` (les props sont comparées superficiellement) supprime les espaces de travail actuels sans demander de confirmation pour les changements non enregistrés, puis rouvre `name` à neuf. Utilisez `onWindowChanged` pour observer l'état de la fenêtre émulée.

## Changements non enregistrés

Transmettez `hasUnsavedChanges` au wrapper `<Workspace2>` :

```tsx copy
<Workspace2 title={t('editVisit', 'Edit visit')} hasUnsavedChanges={formState.isDirty}>
  {/* workspace content */}
</Workspace2>
```

Quand un utilisateur ferme un espace de travail, ferme une fenêtre, change des props incompatibles ou change de groupe, le système vérifie les indicateurs `hasUnsavedChanges` des espaces de travail concernés et affiche une confirmation si nécessaire.

Après l'enregistrement, fermez l'espace de travail sans afficher l'invite de changements non enregistrés :

```ts copy
await closeWorkspace({ discardUnsavedChanges: true });
```
