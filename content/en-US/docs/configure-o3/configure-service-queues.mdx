# Configuring Service Queues

Service Queues is one of the most configurable modules in O3, allowing you to customize queue tables, priorities, statuses, wait-time highlighting, polling, and more. This guide covers all configuration options for the Service Queues module.

## Overview

The Service Queues module manages patient queues in outpatient settings. You can configure:

- Dashboard title and default service queue
- Priority tags with colors and styles
- Wait-time highlighting
- Queue table columns and layouts (per queue/status)
- Concept UUIDs for priorities and statuses
- Calling patients and the queue screen
- The clinic administrator screen
- How often queue data refreshes
- The Add patient to queue workspace
- Visit queue numbers
- Patient chart URLs
- Start Visit form integration

## Dashboard Title

Configure the title displayed on the service queues dashboard:

```json
{
  "@openmrs/esm-service-queues-app": {
    "dashboardTitle": {
      "key": "serviceQueues",
      "value": "Service queues"
    }
  }
}
```

- `key` - Translation key for the title
- `value` - Default text if translation is not found

## Default Service Queue

Set the default service queue selected when opening the start visit form:

```json
{
  "@openmrs/esm-service-queues-app": {
    "defaultInitialServiceQueue": "Outpatient Triage"
  }
}
```

The default is `"Outpatient Triage"`.

## Start Visit Form Integration

The service queues app contributes the `visit-form-queue-fields` extension to the Patient Chart Start Visit form. Those fields render when the Patient Chart config enables service queue fields, or when the Start Visit form is opened from the service queues add-patient flow:

```json
{
  "@openmrs/esm-patient-chart-app": {
    "showServiceQueueFields": true
  },
  "@openmrs/esm-service-queues-app": {
    "defaultInitialServiceQueue": "Outpatient Triage"
  }
}
```

Recommended visit type tabs are also controlled by the Patient Chart Start Visit form. Configure `showRecommendedVisitTypeTab` and `visitTypeResourceUrl` on `@openmrs/esm-patient-chart-app`, not on `@openmrs/esm-service-queues-app`.

## Priority Configuration

Configure priority tags with colors and styles:

```json
{
  "@openmrs/esm-service-queues-app": {
    "priorityConfigs": [
      {
        "conceptUuid": "04f6f7e0-e3cb-4e13-a133-4479f759574e",
        "color": "red",
        "style": null
      },
      {
        "conceptUuid": "f4620bfa-3625-4883-bd3f-84c2cce14470",
        "color": "green",
        "style": null
      },
      {
        "conceptUuid": "dc3492ef-24a5-4fd9-b58d-4fd2acf7071f",
        "color": "orange",
        "style": null
      }
    ]
  }
}
```

**Available colors**: `red`, `magenta`, `purple`, `blue`, `teal`, `cyan`, `gray`, `orange`, `green`, `warm-gray`, `cool-gray`, `high-contrast`, `outline`

**Available styles**: `bold` (or `null` for no special style)

- `conceptUuid` - UUID of the priority concept to configure
- `color` - Color of the priority tag
- `style` - Style to apply (currently only `bold` or `null`)

## Wait Time Highlighting

You can color the wait time shown in queue tables once a patient has waited at least a given number of minutes. This draws attention to patients who have been in the queue a long time. It's off by default.

```json
{
  "@openmrs/esm-service-queues-app": {
    "waitTimeThresholds": [
      { "waitTimeInMinutes": 60, "color": "orange" },
      { "waitTimeInMinutes": 120, "color": "red" }
    ]
  }
}
```

- `waitTimeInMinutes` - The minimum wait, in minutes, before the color applies. Must be a positive number.
- `color` - Either `orange` or `red` (default: `red`)

When more than one threshold matches, the one with the highest `waitTimeInMinutes` wins. In the example above, the wait time turns orange after one hour and red after two. The same thresholds apply to the longest wait shown on the clinic administrator screen.

## Concept UUIDs

Configure concept UUIDs used throughout the service queues module:

```json
{
  "@openmrs/esm-service-queues-app": {
    "concepts": {
      "defaultPriorityConceptUuid": "f4620bfa-3625-4883-bd3f-84c2cce14470",
      "defaultStatusConceptUuid": "51ae5e4d-b72b-4912-bf31-a17efb690aeb",
      "defaultTransitionStatus": "ca7494ae-437f-4fd0-8aae-b88b9a2ba47d",
      "emergencyPriorityConceptUuid": "04f6f7e0-e3cb-4e13-a133-4479f759574e",
      "waitingStatusConceptUuid": "51ae5e4d-b72b-4912-bf31-a17efb690aeb"
    }
  }
}
```

**Key concepts**:
- `defaultPriorityConceptUuid` - Default priority (e.g., "Not urgent")
- `defaultStatusConceptUuid` - Default status (e.g., "Waiting")
- `defaultTransitionStatus` - Status when attending service (e.g., "In Service")
- `emergencyPriorityConceptUuid` - Highest priority (e.g., "Emergency")
- `waitingStatusConceptUuid` - Status for patients waiting to be attended to (e.g., "Waiting"). The dashboard's queue table only lists queue entries in this status, the **Call** action only appears for entries in this status, and the waiting counts and wait times on the dashboard and the clinic overview use it.

## Queue Tables

Configure queue table columns and layouts. This is a powerful feature that allows you to customize table columns per queue and status.

### Column Definitions

Define custom columns or override built-in columns:

```json
{
  "@openmrs/esm-service-queues-app": {
    "queueTables": {
      "columnDefinitions": [
        {
          "id": "patient-name",
          "columnType": "patient-name",
          "header": "Patient Name"
        },
        {
          "id": "custom-identifier",
          "columnType": "patient-identifier",
          "header": "National ID",
          "config": {
            "identifierTypeUuid": "f85081e2-b4be-4e48-b3a4-7994b69bb101"
          }
        },
        {
          "id": "status",
          "columnType": "status",
          "header": "Status",
          "config": {
            "statusConfigs": [
              {
                "conceptUuid": "51ae5e4d-b72b-4912-bf31-a17efb690aeb",
                "iconComponent": "Group"
              },
              {
                "conceptUuid": "ca7494ae-437f-4fd0-8aae-b88b9a2ba47d",
                "iconComponent": "InProgress"
              }
            ]
          }
        },
        {
          "id": "actions",
          "columnType": "actions",
          "config": {
            "actions": {
              "buttons": ["call"],
              "overflowMenu": ["move", "edit", "remove", "undo"]
            }
          }
        },
        {
          "id": "queue-number",
          "columnType": "queue-number",
          "config": {
            "visitQueueNumberAttributeUuid": "c0c579b0-8e59-401d-8a4a-976a0b183519"
          }
        },
        {
          "id": "eligibility",
          "columnType": "extension",
          "header": "Eligibility"
        }
      ]
    }
  }
}
```

**Available column types**:
- `patient-name` - Patient name
- `patient-identifier` - Patient identifier (requires `identifierTypeUuid` in config)
- `patient-age` - Patient age
- `coming-from` - Where patient came from
- `extension` - Custom extension slot column
- `priority` - Priority tag
- `status` - Status with icons (requires `statusConfigs` in config)
- `queue` - Queue name
- `queue-number` - Queue number (requires `visitQueueNumberAttributeUuid`)
- `visit-start-time` - Visit start time
- `wait-time` - Wait time
- `actions` - Action buttons (requires `actions` config)

**Status icons**: `Group`, `InProgress`

**Action types**: `move`, `call`, `edit`, `remove`, `delete`, `undo`

`move` covers moving a patient to another queue and changing their status or priority. The old `transition` action has been merged into it. `transition` is still accepted in configuration but behaves like `move`, so you can drop it from your config.

By default, the actions column shows a **Call** button and an overflow menu with `move`, `edit`, `remove` and `undo`. **Call** only appears for entries in the waiting status. For other entries, the first available overflow action (`move` by default) becomes the button instead. `undo` only appears when the entry has a previous queue entry to return to.

If you override the `actions` column in `columnDefinitions`, list `overflowMenu` explicitly, as the example above does. Otherwise it defaults to `edit`, `remove` and `undo`, without `move`.

**Column configuration options**:
- `id` - Unique identifier for the column
- `columnType` - Type of column. Set it on every column you define, even when it's the same as `id`. A column without `columnType` throws an "Unknown column type from configuration" error.
- `header` - Header text (will be translated if it's a valid translation key)
- `config` - Column-specific configuration:
  - For `patient-identifier`: `identifierTypeUuid` - UUID of identifier type
  - For `status`: `statusConfigs` - Array of status icon configurations
  - For `actions`: `actions.buttons` and `actions.overflowMenu` - Arrays of action types
  - For `queue-number`: `visitQueueNumberAttributeUuid` - UUID of visit attribute containing queue number
  - For `extension`: any extension column renders the `queue-table-<column-id>-slot` extension slot and passes `queueEntry` in slot state. For example, a column with ID `eligibility` renders `queue-table-eligibility-slot`.

### Table Definitions

Define which columns appear in which tables:

```json
{
  "@openmrs/esm-service-queues-app": {
    "queueTables": {
      "tableDefinitions": [
        {
          "columns": [
            "patient-name",
            "custom-identifier",
            "priority",
            "status",
            "actions"
          ],
          "appliedTo": [
            {
              "queue": "some-queue-uuid",
              "status": "some-status-uuid"
            }
          ]
        },
        {
          "columns": [
            "patient-name",
            "coming-from",
            "priority",
            "queue-number",
            "queue",
            "wait-time",
            "actions"
          ],
          "appliedTo": [
            {
              "queue": "",
              "status": ""
            }
          ]
        }
      ]
    }
  }
}
```

- `columns` - Array of column IDs (from `columnDefinitions` or built-in columns)
- `appliedTo` - (Optional) Array of conditions specifying which queues/statuses this table applies to
  - If omitted, applies to all tables
  - Empty `queue` or `status` string means "all queues" or "all statuses"
  - If multiple table definitions match, the first one is used

**Example**: The first table definition applies only to a specific queue and status combination. The second applies to all other queues and statuses, and matches the built-in default. Put specific definitions before the catch-all, because the first matching definition is used.

## Visit Queue Number Attribute

Configure the visit attribute that contains the queue number:

```json
{
  "@openmrs/esm-service-queues-app": {
    "visitQueueNumberAttributeUuid": "c0c579b0-8e59-401d-8a4a-976a0b183519"
  }
}
```

The default is `c0c579b0-8e59-401d-8a4a-976a0b183519`, the Visit Queue Number attribute type from the Reference Application's demo content. The built-in default table shows a `queue-number` column, so if your distribution records queue numbers in a different visit attribute type, set this to its UUID (or set it per column in `columnDefinitions`).

## Default Identifier Types

Configure the identifier types shown in the call patient modal:

```json
{
  "@openmrs/esm-service-queues-app": {
    "defaultIdentifierTypes": [
      "05ee9cf4-7242-4a17-b4d4-00f707265c8a",
      "f85081e2-b4be-4e48-b3a4-7994b69bb101"
    ]
  }
}
```

The call patient modal shows the patient's identifiers of these types.

## Contact Attribute Type

`contactAttributeType` is still in the config schema, but nothing in Service Queues reads it, so setting it has no effect.

## Patient Chart URL

Configure where users are redirected when clicking a patient name:

```json
{
  "@openmrs/esm-service-queues-app": {
    "customPatientChartUrl": "${openmrsSpaBase}/patient/${patientUuid}/chart"
  }
}
```

The URL template supports:
- `${openmrsSpaBase}` - Base URL for the SPA
- `${openmrsBase}` - Base URL for the OpenMRS backend
- `${patientUuid}` - UUID of the patient

## Calling Patients and the Queue Screen

When a user clicks **Call** on a queue entry, Service Queues sends the patient's ticket number and a status string to the queue module's `queueutil/assignticket` endpoint. The queue screen, at `${openmrsSpaBase}home/service-queues/screen`, makes a ticket blink while it has that status.

The default status string is `calling`. If your digital signage expects something else, such as `Now serving`, change it:

```json
{
  "@openmrs/esm-service-queues-app": {
    "callingStatus": "Now serving"
  }
}
```

Avoid `completed`, because the queue backend treats it as a signal to remove the ticket.

## Clinic Administrator Screen

Users with the clinic administrator privilege see two tabs on the Service Queues dashboard. The first, **Clinic overview**, shows numbers for each queue at the selected location, including how many patients are waiting and in service, and the average and longest waits. The second, **Waiting list**, is the standard dashboard. Users without the privilege don't see any tabs, and their dashboard is unchanged.

```json
{
  "@openmrs/esm-service-queues-app": {
    "clinicAdministratorScreen": {
      "privilege": "App: Service Queues Clinic Administrator"
    }
  }
}
```

- `privilege` - The privilege that grants access to the clinic overview (default: `App: Service Queues Clinic Administrator`)

The privilege must exist in your distribution's backend configuration and be attached to a role. The Reference Application's demo content defines it and grants it to the `Organizational: System Administrator` role. Until it's attached to a role, only System Developers see the tabs. Setting `privilege` to an empty string hides the tabs for everyone.

## Refresh Intervals

The Service Queues dashboard and the queue screen poll for updates. Each has one interval for when the user is active and a slower one for when they've gone idle:

```json
{
  "@openmrs/esm-service-queues-app": {
    "refreshIntervals": {
      "dashboard": {
        "active": 60000,
        "idle": 120000
      },
      "queueScreen": {
        "active": 5000,
        "idle": 10000
      }
    }
  }
}
```

All values are in milliseconds and must be between `1000` and `3600000`. The values above are the defaults.

A user counts as idle once they haven't moved the mouse, clicked, typed, touched the screen or scrolled for a minute, or once the browser tab is hidden. Polling stops altogether while the tab is hidden, and the dashboard refreshes as soon as the user comes back to it. The queue screen's idle interval is deliberately short so that an unattended, wall-mounted display stays reasonably current.

## Add Patient to Queue

By default, the **Add patient to queue** workspace lists patients whose visit started today at the selected location and is still open, and who aren't in a queue at that location yet, before the user types a search term. To go straight to search instead, turn this off:

```json
{
  "@openmrs/esm-service-queues-app": {
    "showCheckedInPatientsBeforeSearch": false
  }
}
```
